# 三种基线上的课题定制改进

> 本页保留V6开发阶段说明。最新180次正式验证已完成，使用V6的CC改进与V7的LM/DGEA改进，结果及运行命令见[仓库首页](../README.md)。以下“本阶段”“待验证”描述均指当时的开发状态。

本版本落实2026-10-24确定的研究范围：保留CCGDE3、LMOCSO、DGEA作为基线，在相同修订模型下研究课题定制改进。当前为实现与正确性验证阶段，尚无大规模性能比较结果，不宣称优于基线或达到结项要求。

## 基线与改进的关系

| 入口 | 保留的核心 | 新增的课题处理 |
|---|---|---|
| `CCGDE3` | 仓库已有`CCGDE3_wake`的分组、协作上下文、差分变异与GDE3选择 | 只替换为所有方法共用的V6目标评价器 |
| `CCGDE3_problem` | 分组协作、差分变异、父子支配比较及GDE3选择偏好 | 可行的完整协作上下文；组外物理机位固定、组内数量保持；实际布局去重；整轮之后允许跨组交换 |
| `LMOCSO` | 原竞争配对、速度更新、变异、APD环境选择 | 只替换共用评价器 |
| `LMOCSO_problem` | 竞争配对与原速度更新公式 | 以父布局为锚的可行投影；按真实机位集合去重；保留不同布局的种群；修复改变的速度分量归零 |
| `DGEA` | 原预选择、方向生成及档案更新 | 只替换共用评价器 |
| `DGEA_problem` | 方向引导子代生成公式与档案框架 | 保留方向起点作为可行锚；方向提案转为可行机位变化；档案与种群维护实际不同布局 |

这里的基线仍是仓库声明的Python适配实现。尤其`CCGDE3`沿用已有较强的尾流分组适配版，没有改用较弱随机分组制造改进优势，也没有声称严格复现原论文MATLAB实现。旧算法文件未修改，V6不使用全局函数替换。三个改进版分别保留各自的搜索算子，没有将它们统一改名为同一个通用算法。

连续坐标仍是这些原生算子的内部状态；约束、去重、布局差异、父布局关联及真实评价均以选中N个候选点的集合为准。这是为了兼顾原算法结构与离散选址问题，而非重新声称连续向量差异代表布局差异。

## 统一模型与约束

- 三个目标继续是最大化年发电量、最小化基准LCOE、最小化有效开发包络面积。经济系数与面积定义未为了扩大冲突而改变。
- 新增转子圆盘与尾流截面的解析重叠率，将单源平均亏损按面积加权后平方和合成。顺风距离必须为正，自己的尾流贡献为零。
- 该模型仍采用固定推力系数、15度风向扇区中心及合成地形几何。面积加权后合成不等于逐点转子积分，没有宣称真实山地风场校准。
- 接受的改进版布局必须满足固定N、机位禁布、场界、水平最小间距和坡度禁布。单点或复合交换只改允许组中的物理位置；不能将组外编码数字改变误判为组外机位改变。
- 有界投影失败时保留真实父布局并记录未改变及缓存命中，不注入固定备用布局，不无限重试。
- 最终非支配解集由所有访问过的不同可行布局形成，包含独立的几何检查。

旧模型结果只能作为历史证据。新模型下的算法排名必须重新在同一评价器、候选点、预算和初始化条件下比较。

## 多样性与效率口径

实际布局使用排序后的候选点编号作为身份。种群选择先考虑可行性和非支配层级，再保留各方法原选择偏好，并使用目标距离与选址集合差异处理截断。第一前沿不足时从后续前沿补足，避免LM仅剩少量个体。CC保持各子种群规模及一个完整布局上下文档案；不会将一个40个体子种群误称为100个体全局种群。

机位变化少时复用父布局的平方亏损和，更新移除、加入源对所有保留和新增接收机组的影响。缓存缺失或变化过大时退回完整评价。连接MST与包络面积仍准确重算；增量公式的复杂度优势不等于整个优化器已经得到实际加速。

尾流核按模型和几何指纹保存为只读内存映射，进程可共享文件页。现有地表长度缓存继续使用原来的数值精度设置。

记录请求数、不同可行布局准确评价数、缓存命中、完整/增量尾流评价次数、投影尝试及过滤前重复。CC协作父代重评与真实子代的计数分别以`context_parent_`、`offspring_`开头，不能混淆。过滤后的种群没有重复，不代表搜索没有提出重复布局。

同时保存累计工作会话墙钟时间和进程CPU时间，以及初始化、断点恢复和各模块墙钟计时。墙钟时间可能包含待机和资源争用；`wall_cpu_gap_seconds`仅是诊断值，不能直接当作待机时长扣除。模块时间可能嵌套，不能相加后冒充纯CPU时间。当前不输出性能排名或加速倍数。

## 文件与入口

| 文件 | 内容 |
|---|---|
| `wake.py` | 转子重叠率与共用尾流核 |
| `feasible.py` | 固定数量、固定组外上下文的可行投影与复合交换 |
| `model.py` | 共用三目标评价器、实际布局缓存与增量尾流评价 |
| `engines.py` | 三个冻结基线包装及三个保留原结构的改进版 |
| `run.py` | 单个明确配置的预算执行、完整状态续跑、数据输出 |
| `preflight.py` | 有界数学与功能检查，不是性能实验 |
| `worker.py`、根目录`Start-V6.ps1` | 隐藏的任务计划程序入口、独立日志与重复启动保护 |
| `config.example.json` | 配置格式示例；文件存在不会启动实验 |

输入沿用仓库的WindFLO场景、合成地形与经济参数，不涉及神经网络权重或GPU。地形输入范围限制为现有7000×14000 m局部场区。

重复执行不会覆盖完成项或重复启动同一任务。修改代码后复查应使用新的检查输出目录，保留旧日志。检查包括：解析重叠率与独立积分、部分遮挡边界、上下游与高差、单点/复合交换、组外位置保持、重复与失败计数、增量/完整目标一致、基线包装轨迹一致、六方法共同初始化、相同预算及完整状态续跑。

查看本次进度和新日志：

```powershell
Get-Content -LiteralPath 'D:\suanfa\github_public\windfarm-layout-optimization\verification\v6_check_20261024_b\progress.json'
```

## 后续正式执行的约定

`Start-V6.ps1 -Mode Run`只接受一个明确的配置文件和输出目录，不自动扩展成整批实验。配置示例为1600候选点、400台风机、100个初始个体、10000次请求；本阶段没有启动该示例。正式比较时三条基线和三条改进路线均需使用冻结后的同一模型与配对初始化。

运行输出目录包含`manifest.json`、`progress.json`、完整`last.pkl`、`evaluations.npz`、`trace.json`、`case_metadata.json`和完成后`DONE.json`。`last.pkl`保存求解器、种群、速度或方向状态、随机数、缓存、记录和预算，而非仅保存最终解。已有进度但缺少完整检查点时拒绝fresh重启；源码、依赖或配置变化时拒绝在原目录继续。

暂停可在该次输出目录创建`PAUSE_REQUEST.json`；求解器在保存完整检查点后退出。移除此标记并再次启动相同配置即续跑，保留日志。关闭查看日志的终端或Codex不会结束已成功交给任务计划程序的任务；电脑仍须保持开机，睡眠或注销可能中断执行。

在得到正式对照之前，三个`_problem`入口均应称为待验证改进版。更高可行率、零种群重复或通过功能检查，均不能单独作为结项或优于基线的证据。
